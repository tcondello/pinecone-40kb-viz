How bytes are counted. Pinecone measures the UTF-8 byte size of the flat JSON-stringified metadata object. The calculator sums braces {} (2 bytes) plus each field's ,"key":<value> cost from the table above, minus 1 byte since the first field has no leading comma.


    
Tokens to bytes. The widget assumes ~4 chars/token — the standard English BPE approximation. Non-ASCII text (accented characters, CJK, emoji) costs 2–4 bytes per character in UTF-8, so a 1024-token Japanese chunk can be double the size shown. Build in headroom for multilingual corpora.


    
Pinecone metadata rules.

    
    
      
  • Metadata must be a flat JSON object — no nested objects.
    • 
      
  • Keys must be strings and cannot start with $.
    • 
      
  • Values must be string, integer, floating point, boolean, or list of strings. Nothing else.
    • 
      
  • Integers are stored as 64-bit floats internally — the wire JSON keeps your digits, but beyond 253 you lose precision.
    • 
      
  • Null values are not supported. Remove the key instead of setting it to null.
    • 
      
  • Lists can only contain strings. To store numeric-looking values in a list (like ["85","92"] from the docs example), they must be stringified first.
    • 
    


    
Filtering implications. Booleans support only equality operators. Range operators ($gt, $lt, etc.) work on numbers only. $in and $nin each accept up to 10,000 values per filter. If you need range-like filtering on categorical data, store it as numbers, not strings.


    
Pre-upsert guardrail. Use new TextEncoder().encode(JSON.stringify(metadata)).length in JS (or len(json.dumps(metadata).encode('utf-8')) in Python) before upsert and reject or truncate around ~35 KB to leave safety margin for tokenizer variance and multi-byte characters.
